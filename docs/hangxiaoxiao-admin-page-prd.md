# 杭小消后台页面级 PRD

## Problem Statement

杭小消后台原型已覆盖知识采集、审核、查询、治理、内容运营、AI 获客和系统管理，但需求规则分散在对话、原型和说明文档中。产品、研发和测试无法在当前页面直接确认字段含义、按钮权限、状态流转及异常边界，容易把原型演示误当成真实后端能力，或遗漏人工审核和权限约束。

## Solution

在每个后台页面右侧提供“页面 PRD”入口，点击后打开字段级 PRD 抽屉。抽屉不离开当前页面，统一展示页面目标、角色权限、业务规则、字段定义、按钮结果、状态流转、异常状态、通知日志、验收标准和技术评估项。

营销物料虽然共用一个路由，但 PPT、朋友圈图文、海报和公众号文章分别维护独立 PRD。未进入当前产品范围的微官网、移动端和 BOSS 后台不在本文件展开。

## User Stories

1. As a 产品经理, I want to view the PRD beside the current prototype page, so that I can review requirements without switching documents.
2. As a 研发人员, I want field, state, permission and exception rules, so that implementation does not rely on guessing from UI.
3. As a 测试人员, I want page-level acceptance criteria, so that test cases can trace back to confirmed requirements.
4. As a 项目负责人, I want reused AI 获客 capabilities and 杭小消 differences stated together, so that reuse boundaries remain clear.

## Global Product Rules

- 杭小消按 AI 获客 SaaS 多租户产品设计，共用登录地址，根据账号加载租户品牌、功能、菜单、权限和数据。
- 租户功能由 BOSS 后台开通；杭小消系统设置不展示功能开关。
- 权限覆盖功能、页面、数据和按钮；成员可绑定多个角色，最终权限取并集。
- 用户上传资料完成解析及异常检查后，无异常默认审核通过，自动发布到企业大脑；存在异常转人工审核。检查未完成、失败或结果缺失不得按无异常放行。采集内容、优化建议和实体关系仍按原人工审核流程处理。
- 正式知识已发布版本不可覆盖，修改生成新版本；下架或归档后保留审计与历史引用。
- 不支持知识内容批量导出；仅支持日志和统计报表按权限导出。
- 用量由平台手动增加额度，不提供在线购买。
- 站内通知规则由系统固定，通知按账号、角色和功能权限推送。
- 页面只保留字段标签、数据、状态、操作及会影响结果的业务边界；重复页面标题、重述可见操作或仅解释界面的描述文案不展示。
- 微官网为独立后台，本 PRD 不重复定义微官网需求。
- 后台仅建设 PC 端，不承诺移动端适配。

## Page Requirements

### 运营工作台

- 角色：系统管理员、知识管理员、审核人员及具有查看权限的成员。
- 操作字段：查看运营大屏、上传知识。
- 指标字段：正式知识、今日采集候选、待人工处理、知识调用。
- 待办字段：任务、来源、风险、状态、操作。
- 采集字段：渠道分组、最近同步/运行说明、运行状态。
- 状态：上传资料检查无异常后自动通过并进入企业大脑；异常上传进入知识审核并保留文件与异常原因。去审核和查看缺口保留任务上下文。

### 运营大屏

- 定位：面向领导检查、项目展示和公众参观的只读展示页面，不展示内部项目成果。
- 字段：知识采集量、新增入库量、知识总量、当前咨询在线人数、平均响应时长、知识资源概览、知识与服务增长趋势、热点咨询、咨询分类占比、咨询时段分布、平台可用率、智能问答响应率、运行渠道和系统运行稳定状态。
- 统一统计约定：所有自然日、自然周、自然月及滚动窗口均使用 `Asia/Shanghai`；大屏必须展示统计截止时间。自然周从周一 00:00 开始，自然月从每月 1 日 00:00 开始。“近 30 日”为 `[统计截止时间-30天, 统计截止时间)`。
- C端数据边界：咨询指标只统计通过杭小消公众服务 API 产生的消费者会话，不统计后台工作人员、API 调用次数、机器巡检、测试、演示或爬虫流量。
- 操作：全屏展示、退出大屏。
- 异常：指标不可用显示 `--`；数据源延迟展示更新时间，不展示内部错误栈。

### PPT

- 列表布局：不展示顶部数量、生成中、可下载和最新版本统计，页面标题与操作区下方直接展示 PPT 列表。
- 列表字段：PPT名称、页数、知识与VI引用、场景、版本、生成时间、状态、操作。
- 创建字段：生成要求、补充资料、企业大脑引用、VI版本、大纲页标题、核心结论、证据、版式建议。
- 操作：新建、生成大纲、审核大纲、生成PPT、预览/编辑、下载PPTX、下载PDF。
- 状态：草稿、生成中、待审核、可下载、生成失败；失败保留任务并支持重试。

### 朋友圈图文

- 字段：图文名称、知识引用、品牌视觉、封面、正文、CTA、配图、状态。
- 操作：新建、预览、编辑、导出图文包。
- 边界：不自动发布；导出内容保留AI标识、知识引用和人工审核状态。

### 海报

- 字段：海报名称、主标题、主视觉、CTA、尺寸、知识引用、品牌视觉、状态。
- 操作：新建、预览、编辑、下载。
- 边界：涉及政策、数据、价格和服务承诺时必须人工确认。

### 公众号文章

- 授权字段：公众号名称、授权状态、发布权限、数据权限、自动发布开关。
- 文章字段：标题、摘要、正文、封面、配图、知识引用、状态。
- 操作：新建、预览、编辑、审核并发布、同步数据、查看数据详情。
- 回流字段：阅读、分享、在看、新增关注、同步状态和更新时间。
- 状态：草稿、待审核、发布中、已发布、发布失败；未授权不得发布和回收数据。

### AI获客总览

- 字段：能力名称、适用场景、任务数量、运行状态、最近结果。
- 入口：运营计划、爆款追踪、AI混剪、营销视频、数字人。
- 规则：底层能力复用AI获客；杭小消只加载已开通能力、品牌和权限。

### 运营计划

- 页面目标：企业 Agent 根据企业档案、正式知识、业务数据、热点和反馈生成周计划或月计划，先解释“为什么生成、计划怎么做”，人工确认后才批量创建正式任务。
- 列表筛选：全部、周计划、月计划。周计划按自然周查询，支持选择周内任意日期；月计划按自然月查询；统一使用 `Asia/Shanghai`。
- 列表字段：计划类型、计划周期、计划名称、核心目标、生成时间、状态、任务数、执行进度、操作。待确认显示“拟任务 N 项”，确认后显示“正式任务 N 项”。
- 生成依据快照：企业现状、经营目标、数据来源与周期、变化信号、正式知识 ID 与版本、AI 判断、信息缺口、置信度、Prompt 版本、模型和生成时间。快照不可被后续企业数据反向改写。
- 计划方案：核心策略、执行节奏、已开通渠道、负责人、风险边界、预期结果和拟任务列表。
- 拟任务字段：任务名称、任务类型、计划日期、渠道、业务能力、负责人、风险等级、预期结果、任务依据。点击调整进入独立拟任务详情，保存后仍为拟任务。
- 计划确认：只调整有问题的拟任务，未调整任务默认接受；点击“确认并生成任务”后，在同一事务中批量创建全部正式任务并进入执行中。
- 幂等与事务：以 `plan_id + plan_version` 为幂等键；重复提交返回原结果，不重复生成任务；任一步失败整批回滚，计划保持待确认。
- 重新生成：仅待确认或生成失败版本可重新生成；读取最新企业情况创建新版本，旧版本归档并保留原快照与替换原因。
- 状态：生成中、生成失败、待确认、执行中、已完成、已归档。
- 权限：查看、调整拟任务、重新生成、确认、归档分别校验按钮级权限；数据只限当前租户和账号授权范围。
- 异常：负责人停用或无权、任务日期越界、必填字段缺失时禁止保存或确认；数据不足时展示缺失项、影响范围和低置信度；生成失败版本不保留可确认半成品。
- 边界：不提供手工新建计划；确认不自动对外发布、发送消息、报价或承诺结果；AI 预期结果不计入真实经营数据。

### 爆款追踪

- 字段：热点主题、来源平台、内容链接、热度、增长趋势、对标结构、采集时间、状态。
- 操作：刷新、查看拆解、加入追踪、带入AI混剪或营销视频。
- 边界：热点内容仅作选题和结构参考，不直接作为正式知识或事实依据。

### AI混剪

- 输入字段：素材、参考链接、手工口播、目标渠道、CTA开关与文案。
- 生成字段：拆解结构、改写脚本、镜头、字幕、配音、封面、状态。
- 操作：抓取参考、生成脚本、调整、确认、生成成片、预览、下载。
- 边界：只复用结构；事实与表达必须基于杭小消正式知识。

### 营销视频

- 字段：视频标题、目标渠道、参考链接、正式知识依据、脚本、封面、分镜、CTA、状态。
- 操作：新建、选择热点、生成内容方案、确认、生成视频、预览、归档。
- 状态：知识待确认、内容生成中、待审核、生成中、已完成、失败。

### 数字人

- 资源字段：形象名称、形象授权、声音名称、声音授权、额度。
- 任务字段：任务名称、脚本、知识来源、形象、声音、状态、生成时间。
- 操作：申请增加形象、创建任务、预览、下载。
- 边界：只可使用已授权形象与声音；生成内容保留AI标识和知识来源。

### 知识审核

- 列表结构：知识候选和优化建议共用一个任务列表，不使用两个页签，也不拆成两个列表。无异常上传不产生待人工审核任务；异常上传、采集候选与优化建议进入本列表。
- 筛选字段：任务类型、模糊搜索、分类多选；任务类型包括全部、知识候选、优化建议。
- 来源字段：来源名称、渠道、推荐知识域、候选数量、审核状态。
- 候选字段：标题、正文摘要、分类、标签、适用范围、证据定位、冲突状态。
- 优化建议字段：建议类型、关联正式知识、触发原因、信号、学习价值、状态。
- 操作：两类任务均使用“处理/收起”展开详情；列表行级操作固定在最右侧，展开后的“查看原文”和审核操作也在详情右侧对齐。知识候选支持调整、通过、驳回，优化建议支持采纳、忽略。
- 原文查看：网页来源打开原始链接；上传文件使用原文预览并定位页码或段落；优化建议定位到关联正式知识的证据原文。无原文权限时不展示入口，原文失效时展示留存快照和失效提示。
- 结果：采纳优化建议后生成新版本候选，再进入人工审核，不直接覆盖正式知识。
- 跳转：进化治理、知识反馈和维护中心进入本页时，自动筛选“优化建议”。
- 权限：拥有当前页面对应按钮权限即可处理，不分配审核人。
- 状态：待审核、有冲突、已通过、已驳回；驳回原因必填。

### 通知中心

- 入口：登录后的顶部通知中心按钮；使用侧边抽屉，不增加菜单和独立路由。
- 通知类型：知识审核、审核结果、采集异常、知识治理、内容任务、发布与回流、额度、安全。
- 字段：通知标题、通知类型、摘要、触发事件、接收对象、关联对象、发生时间、已读状态、处理状态、跳转目标。
- 接收规则：按当前租户、账号、角色、功能、页面及按钮权限生成账号级通知；规则由系统固定，不提供租户配置开关。
- 操作：查看详情、收起详情、去处理、全部标为已读、查看 PRD、返回通知中心。
- 已读状态：未读、已读；仅影响当前账号。查看详情或去处理后标为已读。
- 处理状态：待处理、已处理、已失效；已读不等于已处理。
- 跳转：去处理关闭抽屉并进入对应目标页面，保留任务标识和必要筛选；目标页面再次校验按钮权限。
- 异常：目标已处理时展示结果且不再显示执行按钮；目标不存在时标记已失效；无目标权限时隐藏去处理；标记已读失败时恢复原状态。
- 边界：不提供通知规则配置、订阅偏好、短信/邮件/企业微信推送、通知删除、批量导出和通知搜索。
- PRD入口：通知中心抽屉底部展示“查看 PRD”，同一抽屉切换到字段级 PRD；返回后保留未读数和原列表状态。

### 企业大脑

- 查询字段：关键词、检索模式、消费领域、内容模态、内容分类、热点专题。
- 结果字段：标题、知识域、分类、标签、来源、更新时间、版本、状态。
- 操作：上传资料、搜索、清空、查看原件、反馈有误、详情、版本、修订、保存草稿、提交审核、下架与恢复申请。
- 全局使用规则：正式知识自动审核或人工审核发布后默认进入当前租户全局知识能力，不提供逐条“引用知识”。下游调用仍受功能开通、角色权限、数据范围、适用范围和知识状态控制。
- 交互边界：知识查询页不展示“引用知识”按钮，不打开功能选择弹窗，也不产生手工引用状态。
- 管理字段：自动分组、正式知识分组、内容类型、权限摘要。
- 边界：只查询已发布、当前有效且账号有权访问的正式知识；不提供新建知识和批量导出。

### 查询标签与知识生命周期（2026-10-08 补充）

- 查询中消费领域、内容模态、内容分类、热点专题及知识标签分别默认展示最相关的 30 个标签，不足 30 个全部展示；“不限”不占名额。按当前查询词与有权检索的有效知识计算关联度，关联度相同按有效知识覆盖数、更新时间、名称稳定排序。
- 支持人工增加已有标签到展示区、移除展示标签及恢复推荐。人工增加可超过默认 30 个；已选标签保持可见，不因推荐变化而静默取消筛选。移除已选标签时必须同时明确取消该筛选。展示配置与知识内容标签是两类对象，前者不修改知识、不触发知识审核。
- 知识标签支持多选 AND（全部匹配）/OR（任一匹配），并与原领域、模态、分类、专题、关键词共同生效。结果支持相关性、更新时间升降序、分类排序；切换排序不清空筛选。结果数、列表与详情保持一致。
- 编辑知识标题、正文、标签、分类或适用范围先保存修订草稿；草稿/驳回可编辑并提交，待审核只读。旧正式版本在审核期间继续有效，通过后发布新版本，驳回保留原因；相同审核动作不可重复发布。
- 草稿保存基础版本；审批时若当前版本已变化，则阻止发布并要求基于最新版本重新修订。历史版本保留内容快照、时间、来源与引用关系，不被新版本覆盖。
- 下架原因必填，下架后进入归档区并立即退出新检索和新问答；历史咨询仍能追溯当时版本。恢复生成新的待审修订，重新审核前不得进入查询。
- 关键验收：修订不改变正式知识，通过后查询展示新版本；下架后搜索与问答不再命中，恢复需审核；标签默认上限、人工增减、已选保留及多条件排序各自可验证。

### 版本冲突处置（2026-10-08 补充）

- 比较旧版与候选版的标题、正文、标签、适用范围和版本，提供来源定位/证据锚点与受影响知识 ID、标题及版本。
- 人工选择保留旧版、采用新版或按适用范围拆分。保留旧版结束当前候选；采用新版生成新正式版本；拆分必须填写不同适用范围，保留两条可区分知识及其来源，不静默覆盖事实。
- 处置前校验候选状态及基础版本；已处理或过期候选不得重复发布。处置方式、理由、操作者、时间、旧新版本及受影响对象写入审计。

### 多模态问答与复验（2026-10-08 补充）

- 入口在进化治理的问答测试区；支持文本问题、图片/文档附件以及内部/外部使用视角。内部可用范围包含公开知识与当前账号有权访问的内部知识，外部只能使用可公开服务的知识。
- 先过滤未发布、下架、归档、过期、尚未生效或无权知识；同一知识只采用当前最新有效版本，再按相关性排序。相关性相当时优先发布时间/更新时间最新的有效知识，版本号仅用于同知识比较。新但不相关的知识不得优先于相关知识。
- 回复展示回答、依据知识 ID、版本、来源时间，以及可用的图文、视频或政策资料卡片。素材须在有效期与授权范围内；失效素材显示不可用原因，保留有效文字依据，不虚构可访问链接。
- 附件解析失败明确报错，不假装已识别；低命中或依据不足提示补充问题或转人工。原型模拟附件解析与回答，不调用真实 OCR、模型或公众服务 API。
- 测试集保存问题、使用视角、预期知识、首次回答及引用快照、人工评价；知识修订后可复验，比较前后命中、版本与预期一致性。历史测试快照不随知识修改变化，测试和演示流量不计公众统计。

### 成品归档与采集批次（2026-10-08 补充）

- 成品回库须填写成品名称、asset ID、模态、来源知识 ID/版本、版权/授权、适用范围与用途。成品以独立知识对象生成审核候选，审核通过后才被检索与问答引用；禁止用来源事实知识 ID 作为成品 ID，禁止反向覆盖来源事实。
- 按成品任务/来源标识及成品版本幂等，重复归档返回已有候选或正式对象。素材状态与审核状态联动；源知识下架或授权失效时提示重新核验。
- 采集批次记录来源渠道、采集时间、条目 ID、新增/变更/重复/失败分类、错误原因、候选 ID、审核状态和发布知识版本。新增/变更与待审/入库是不同统计维度，不能相加作为总量。
- 支持查看条目和仅重试失败项；成功项与重复项不得被重试复制。采集及重试成功仍进入人工审核；变更条目生成新版本或冲突候选，不直接覆盖现有正式版本。
- 本周新增入库按本自然周首次发布的 knowledge ID 去重，知识更新按本周发布新版本的已有 knowledge ID 去重；失败、重复、待审不计入周更成果。

### 消费者咨询追溯（2026-10-08 补充）

- 日志与审计增加用户 ID、会话 ID、多轮问题和回答、问答类型/附件处理状态、每轮时间、满意/不满意/未评价、引用知识 ID 及当时版本。

### 上传资料自动审核

- 适用范围：运营工作台“上传知识”与企业大脑“上传资料”使用同一流程；本次不改变自动采集、优化建议与图谱的人工审核规则。
- 流程：上传 → 解析及异常检查 → 无异常默认通过并发布到企业大脑；异常 → 知识审核 → 人工处理后发布或驳回。
- 无异常条件：解析成功，所有必需检查完成且结果明确无异常；检查覆盖内容及版本冲突、必要信息与来源、适用范围、隐私及使用权限。检查阈值由技术方案定义，不以模型置信度或没有错误提示替代完整检查结果。
- 异常包括版本/事实冲突、来源或适用范围缺失、隐私或使用权限待核验、解析或检查失败。检查中、结果缺失或不完整时保持未发布；失败保留原因并进入人工处理。
- 自动通过结果：发布新知识版本，进入企业大脑查询和管理，继承资料数据权限并供已开通功能按权限调用；不生成待人工审核任务，不覆盖已发布旧版本。
- 留痕：记录上传任务、来源、检查结果、审核方式（自动/人工）、时间、知识 ID 和版本。相同上传任务重复回调不重复入库或生成日志。
- 原型边界：弹窗内“原型演示设置”提供无异常、冲突、信息缺失、检查失败、检查中场景；选择文件不会触发真实解析、模型检查或后端入库，演示记录刷新后重置。
- 验收：无异常上传可立即在企业大脑找到并有自动审核日志；异常上传有对应候选及原因且不可被正式知识检索；未选文件或检查未完成不得发布。

## 统一指标计算口径

### 全局规则

- 时区：`Asia/Shanghai`；今日、自然周和自然月均以该时区切分。
- 权限：只统计当前租户与当前账号数据权限范围；运营大屏按授权后的租户汇总口径展示。
- 格式：整数不保留小数；百分比和分值默认保留 1 位小数。
- 空值：分母为 0、核心数据源不可用或没有上一比较窗口时显示 `--`，不伪造 `0%`。
- 延迟：页面展示最近成功更新时间；演示数据和 AI 预测值不进入真实指标。
- 下钻：统计卡点击后的下钻明细必须继承同一时间、状态、去重、租户和权限条件。
- 版本：每次计算保存 `metric_version`；公式、权重、过滤条件或数据源口径变化时升级版本，历史结果不静默回算。
- 刷新：通知与额度由业务事件触发实时刷新；运营工作台、知识审核和任务统计不超过 1 分钟；运营大屏不超过 15 分钟；知识图谱、进化治理和质量分值每小时刷新，人工审核后立即增量刷新；第三方指标以最近一次同步成功时间为准。

### 运营工作台与运营大屏

| 指标 | 计算公式 | 纳入、排除与去重 |
| --- | --- | --- |
| 正式知识 | 当前版本为已发布、未下架、未归档、未过期的知识数量 | 按 `knowledge_id` 去重；排除无权数据 |
| 今日采集候选 | 今日采集任务产生且状态为待审核或有冲突的候选数量 | 按 `candidate_id` 去重；排除已通过、已驳回和跨租户数据 |
| 待人工处理 | 至少包含一个待审核、有冲突或待人工补全项的任务数量 | 按 `review_task_id` 去重 |
| 知识调用 | 统计周期内权限校验通过且调用成功的问答、AIGC、数字人等事件数 | 按 `call_event_id` 去重；失败和越权事件不计入 |
| 知识采集量 | 平台上线至统计截止时间，采集成功、已持久化并形成可审核候选的来源内容数 | 同一来源 URL、发布时间和内容指纹生成唯一 `acquisition_item_id`；失败、内容重复、附件拆分和跨租户记录不计入 |
| 新增入库量 | 本自然周内首次审核发布的正式知识数；自然周为周一 00:00 至统计截止时间 | 按 `knowledge_id` 去重；历史知识发布新版本不算新增；撤回后重发不重复计数 |
| 知识总量 | 统计截止时间处于已发布、未下架、未归档且未过期状态的正式知识数 | 按 `knowledge_id` 去重；同一知识的多个版本只计当前有效版本 |
| 当前咨询在线人数 | 近 5 分钟内通过杭小消公众服务 API 产生咨询、搜索或问答活动的 C端独立会话数 | 按 `service_session_id` 去重；同一会话多次 API 调用只计 1；排除后台账号、机器巡检、压力测试、演示和爬虫流量 |
| 平均响应时长 | 近 30 日成功咨询请求从 API 网关接收请求到返回首个有效应答片段的耗时总和 ÷ 成功咨询请求数 | 按 `request_id` 去重；排除客户端网络传输、用户取消、重复重试、测试请求和未产生有效应答的失败请求 |
| 知识域数量 | 统计截止时间已启用的一级知识分类数 | 按 `knowledge_domain_id` 去重；停用和仅用于测试的知识域不计入 |
| 知识来源渠道 | 已完成来源认证且当前启用的采集来源数 | 按 `source_channel_id` 去重；同一机构下不同站点或公众号分别计数；停用和测试来源不计入 |
| 多模态内容量 | 当前有效知识关联的文本、图片、音频和视频素材对象总数 | 按 `asset_id` 去重；链接只作引用不计素材；同一知识关联多个素材分别计数；下架、损坏和无权素材不计入 |
| 今日新增知识 | 本自然日 00:00 至统计截止时间首次审核发布的正式知识数 | 按 `knowledge_id` 去重；历史版本更新和撤回重发不计入 |
| 本月知识更新 | 本自然月内至少发布过一个新版本且非首次入库的正式知识数 | 按 `knowledge_id` 去重；同一知识当月多次发布新版本只计 1；仅编辑未发布不计入 |
| 知识与服务增长趋势 | 逐自然月展示月末知识总量和当月有效咨询会话数；两条序列分别按自身量级展示趋势，不比较绝对值 | 知识总量按 `knowledge_id`；公众服务次数及咨询会话按 `service_session_id`；有效会话至少包含 1 个有效 C端问题并返回回答、合规拒答或澄清 |
| 近 30 日服务增长 | （近 30 日有效咨询会话数－此前 30 日有效咨询会话数）÷ 此前 30 日有效咨询会话数 × 100% | 两个窗口相邻且等长；对比期为 0 显示 `--` |
| 知识引用准确率 | 近 30 日人工有效抽检中，回答引用内容与原文事实一致且来源链接可追溯的引用项数 ÷ 全部有效抽检引用项数 × 100% | 按 `citation_sample_id` 去重；撤销、未完成和无结论抽检不进入分母；保存抽检规则版本 |
| 热点咨询 | 近 30 日有效咨询会话按主问题语义归并为主题后，按主题会话数倒序取前 5 | 同一 `service_session_id` 只进入 1 个主主题；低置信度主题人工复核后计入；排除无效和测试会话 |
| 热点涨幅 | （本期主题有效会话数－上期同主题有效会话数）÷ 上期同主题有效会话数 × 100% | 本期与上期均为相邻 30 日；上期为 0 显示“新增”而非百分比 |
| TOP 5 咨询覆盖率 | 前 5 个热点主题有效会话数之和 ÷ 全部有效咨询会话数 × 100% | 每个 `service_session_id` 只计入 1 个主主题，避免跨主题重复 |
| 咨询总量 | 近 30 日有效咨询会话数；有效会话至少包含 1 个有效 C端问题并返回回答、合规拒答或澄清 | 按 `service_session_id` 去重；排除空会话、后台账号、机器巡检、测试、演示和爬虫流量 |
| 咨询分类占比 | 某主分类有效咨询会话数 ÷ 咨询总量 × 100% | 按 `service_session_id` 去重；每个会话依据主要诉求只归 1 个主分类；无法可靠分类的进入“其他咨询” |
| 咨询时段分布 | 按有效咨询会话开始时间归入 00–04、04–08、08–12、12–16、16–20、20–24 六个时段 | 按 `service_session_id` 去重；使用 `Asia/Shanghai`；跨时段会话只按开始时间计入 1 组 |
| 平台可用率 | 近 30 日关键服务成功健康检查次数 ÷ 应执行健康检查次数 × 100% | 按 `health_check_id` 去重；仅排除提前登记、明确时间且已公告的计划维护；临时故障、超期和未公告维护计入失败 |
| 智能问答响应率 | 近 30 日内 10 秒内返回回答、合规拒答或澄清的有效咨询请求数 ÷ 全部有效咨询请求数 × 100% | 按 `request_id` 去重；超时、异常和空响应计失败；排除用户取消、重复重试、测试和机器巡检请求 |
| 运行渠道 | 当前已启用且近 5 分钟最后一次健康检查成功的采集、问答、内容发布和数字人接口渠道数 | 按 `channel_id` 去重；停用、测试、检查失败或超过 5 分钟未上报的渠道不计入 |
| 系统运行稳定 | 采集、智能问答、内容发布和数字人服务四类关键模块均通过最近一次健康检查，且近 5 分钟无 P1/P2 未恢复告警 | 每类模块至少配置 1 个健康检查；任一模块失败、超时或缺少心跳均不显示“稳定” |

运营大屏指标接口必须同时返回 `metric_version`、`statistical_period`、`cutoff_at`、`refreshed_at` 和 `data_status`。当 `refreshed_at` 距当前时间超过约定刷新周期 2 倍时，页面显示“数据延迟”；分母为 0 或数据不可用时显示 `--`，不得显示 `0` 冒充有效结果。

### 进化治理

质量子分先归一化到 0—100；页面和结果同时保存子分、权重、计算时间和公式版本。

| 指标 | 计算公式 | 纳入、排除与去重 |
| --- | --- | --- |
| 知识可信度 | `30% × 来源权威性 + 25% × 证据完整性 + 20% × 时效性 + 15% × 冲突健康度 + 10% × 审核完成度（含自动及人工通过）` | 有未解决事实冲突时冲突健康度为 0 |
| 内容质量与效果 | `35% × 内容完整性 + 25% × 正向反馈率 + 20% × 有效使用率 + 20% × 业务结果达成率` | 缺少业务结果时其余权重等比归一，并标记部分数据缺失 |
| 学习价值 | `35% × 问题频次 + 30% × 业务影响 + 20% × 负向反馈 + 15% × 时效紧迫性` | 只用于建议排序，不使建议自动生效 |
| 即将到期 | 距适用截止日大于 0 且小于等于 30 天的正式知识数 | 按 `knowledge_id` 去重 |
| 版本冲突 | 尚未人工解决的有效版本冲突数 | 按 `conflict_id` 去重 |
| 知识缺口 | 尚未补全、忽略或失效的语义缺口簇数 | 按 `gap_cluster_id` 去重 |
| 适用范围缺失 | 必要适用范围字段缺失或校验未通过的正式知识数 | 按 `knowledge_id` 去重 |
| 知识域维护状态 | 已完成维护检查项 ÷ 当前周期全部应维护检查项 × 100% | 无应维护项时显示 `--` |
